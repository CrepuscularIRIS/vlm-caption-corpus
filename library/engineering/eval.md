# 工程卡：评测、种子与统计

由 `cards/pattern/*/` 各卡"工程经验"节与 `F5_stop_eval/engineering_lessons.md` 去重汇总（自动按关键词分组，一条只归一组）。括号内为原论文出处；行首为来源卡。

- `PC-F1-03` 当效率只在成功集合中标准化时，应同时记录四项：$|Q|$、Q 内 T 方差、零调用成功样本数、各通道 token 质量（2604.08545 lesson）。
- `PC-F1-04` 当成本乘在成功奖励上时，应当逐项检查四件事：零成功组、format 残余奖励、历史目标的更新顺序、无工具支撑。之后再用配对的得失题判断准确率是否真的保住（2504.14870 lesson）。
- `PC-F1-09` 当离散模式标签可能与真实计算脱钩时，先测模式之间的能力差和生成长度，再设计奖励；训练时的硬上限与部署时无上限的行为要分别报告（2608.20256 lesson）。
- `PC-F2-03` 当用共享图估值时，应先验证状态等价，并报告 floor 与单例的比例；不能把数学上收敛当作估计正确（2609.35084 lesson）。
- `PC-F2-11` 当评估器冻结时，应独立记录其可迁移性与置信校准；对→对的奖励不能解释为对冗余工具的惩罚（litscan:65503 lesson）。
- `PC-F2-14` 当同 batch 复用动作信用前，应验证历史条件可比，并分开报告匹配覆盖率、因果必要性与真实成本（2606.05784 lesson）。
- `PC-F2-19` 当工具准确率上升时，先对齐同 checkpoint 的无工具参考与固定失败 cohort，并报告 gain 与 harm 两边；不要只看调用率或净差（litscan:76529 lesson）。
- `PC-F3-01` 当 SFT 后单独评测掉分时，不要直接判冷启动无效，应在同一 RL 预算下比较（litscan:63682 Table3、2507.03019 Table4）。
- `PC-F3-02` 当用 0/k 判定"不可解"时，换种子重采一次（litscan:76968）。
- `PC-F3-12` 当训练提示在部署不可用时，必须有迁移项并在无提示下评测（rs.why_non_obvious）。
- `PC-F3-16` 当 0/k 题被删时，至少用另一模型或另一种子复查（2608.02217 S2）。
- `PC-F3-19` 当回放与新任务冲突时，同时报告主任务分数（litscan:72124 Table10）。
- `PC-F4-16` 用判官同时筛查与验收时**：单独测人类一致性并更换检测器；事实正确性与答案收益要分开报告（litscan:67495 lesson）。
- `PC-F4-17` 降 caption 幻觉时**：同时报告长度、覆盖率和自然度（litscan:77491 lesson）。
- `PC-F4-18` 降低主输入信息、迫使模型用工具时**：检查大 crop 是否绕过了约束，并分别报告信息预算、定位质量和调用必要性（litscan:79625 lesson）。
- `PC-F4-19` 奖励权重用训练来源构造的独立 validation 集选定，不用测试 benchmark 调参（同上 App.D.1 pitfalls）。
- `PC-F5-07` 当用置信度门控视觉补看时，应固定置信度定义（raw logit 还是 softmax）、触发边界（按句号 token 还是按位置）、预算与视觉信息来源，论文公式与代码不一致时以代码为准并单独报告（2603.21754 lesson）。
- `PC-F5-09` 当环境/评测资源可被 agent 写入时，要按 run 隔离环境状态，用真实独立 seed 验证少数候选（2507.04103 lesson、pitfalls）。
- `PC-F5-09` 当多轮评测结果受模板/history 序列化影响时，先固定 harness 再比较算法（2606.00135 relevance P54）。
- `PC-F5-10` 当用配对胜负账本判定时，要保存逐题、逐采样的原始输出，而不是只存汇总准确率，否则事后无法重算（推断，自 2609.36043 与 2610.12601 的逐 item 统计要求）。
- `PC-F5-10` 当 benchmark 版本更新时，必须固定版本号与解析规则，跨版本成绩不能直接相减（2406.19314 relevance P49）。
- `PC-F5-11` 当不同条件的有效样本过滤不同（n=58 vs n=57）时，要保留差异而不是假装全配对（2606.01287 pitfalls）。
- `PC-F5-13` 当工具 API 的定量评测不输出推理、需另用网页重跑做定性分析时，两份结果必须分别归档（2511.01833 pitfalls）。
- `PC-F5-13` 当评测 reasoner 与工具的输入分辨率不同，搜索增益会被分辨率主导，必须对齐输入预算（litscan:72197 pitfalls）。
- `PC-F5-13` 当 benchmark 由强模型过滤构造时，要在报告中标明筛选条件，不能当无偏难度（litscan:72197 pitfalls）。
- `F5-lessons` 当 token-level 平均 loss 除以组内生成 token 总数时，长轨迹在组内总和中占更多项，应当在比较效率方法时单独报告每条轨迹的有效梯度权重。（2607.14547 normalization）
- `F5-lessons` 当报告"重复评测 N 次的平均"（如 Avg@32）时，它不是 N 个独立训练种子，应当分开报告评测重复与训练种子。（2607.14547 seeds）
- `F5-lessons` 当用 bootstrap 估计不确定性时，它只覆盖已观察到的 run/题目，不能替代新训练种子或填补未搜索的配置，应当用真实独立种子验证少数候选。（2507.04103 rs.why_non_obvious；2610.05400 H.5，F1 digest）
- `F5-lessons` 当多轮评测的 prompt 模板/history 序列化改变时，分数可变化 10 点以上（BFCL multi-turn 22.7→37.2 仅换 prompt），应当固定并记录 harness 再比较算法。（2606.00135 Table4）
- `F5-lessons` 当评测环境可被 agent 写入并跨 session 持久时，"成功"可能来自改坏环境，应当按 run 隔离并复位环境状态。（2507.04103 §5 Shortcut-Seeking）
- `F5-lessons` 当工具 API 的定量评测不输出推理、需另在网页端重跑做定性分析时，两份结果不可混用，应当分别归档。（2511.01833 Sec.4.3）
- `F5-lessons` 当 benchmark 用强模型全答对的题剔除构造时，难度是条件选择，应当在报告中标注筛选条件。（litscan:72197 §3.2）
- `F5-lessons` 当评测 reasoner 与工具的输入分辨率不同时，搜索增益会被分辨率主导，应当对齐输入像素预算。（litscan:72197 §3.2/Table2）
- `F5-lessons` 当两个 benchmark 有重叠题（TIR-Bench Visual Search 含 32 个 HR-Bench 题）时，合并计样本量会高估独立性，应当先去重。（2511.01833 conditions）
- `F5-lessons` 当用 selective accuracy 报告弃答/停止方法时，只算留下样本会夸大效果，应当同时报 coverage 与 fallback 效用。（2604.18419 lesson）
- `F5-lessons` 当 judge 与人评一致率只有 88% 左右时，逐任务结果不能视作无误验证，应当报告 judge 误差并对关键结论做人工复核。（2605.06761 §4.1）
- `F5-lessons` 当置信度门控的论文公式（raw logit gap）与代码（softmax prob gap）不一致时，同一阈值不可互换，应当以实际运行的代码口径报告并单独标注。（2603.21754 rs.key_step / invariance）
