# 工程卡：奖励设计与 reward hack

由 `cards/pattern/*/` 各卡"工程经验"节与 `F5_stop_eval/engineering_lessons.md` 去重汇总（自动按关键词分组，一条只归一组）。括号内为原论文出处；行首为来源卡。

- `PC-F1-02` 当用 MaxNorm 时，应同时记录三件事：floor 激活比例、零差组跳过率、reward 与 KL 梯度之比（2609.19164 lesson）。
- `PC-F1-03` 当多奖励先加权后标准化时，权重会消失。应当记录每个通道的尺度与活跃比例，再把权重放到标准化之后（2601.05242 lesson）。
- `PC-F1-07` 应把 natural 主组与 forced 测量分支分开记录：有效与无效计数、逐题标签、控制器前后的奖励（2607.08572 lesson）。
- `PC-F1-11` 当操作 token 只占少量输出时，应核对稀疏位置的相对权重和使用奖励带来的投机（2605.15198 lesson）。
- `PC-F1-14` 当提高中间视觉表示质量时，要把触发次数与有效内容分开；不能用额外的调用奖励把次数增长当作能力增长（2606.00562 lesson）。
- `PC-F1-14` 当操作 token 只占少量输出时，要联合核对使用奖励与计数惩罚（2605.15198 lesson）。
- `PC-F2-07` 当逐前缀奖励最终被聚合时，要明确"标量广播"与"按步路由"的区别（2602.01034 lesson）。
- `PC-F2-10` 当反事实 bonus 改善答案时，应分别审计奖励输入、被更新的 token 和采样分布；否则无法推断裁图动作的信用（litscan:76688 lesson）。
- `PC-F2-11` 当过程奖励鼓励验证时，先检查它是否被转化成了更多工具调用；正确性门控也不能代替调用校准（2609.08025 lesson）。
- `PC-F2-13` 当过程 judge 只懂局部合理性时，聚焦最差分只能延缓投机；要保留 GT 终端信号，并分组监控正确长重复与空回答（2504.15275 lesson，Stop Summation，同属"PRM 驱动 RL"的教训）。
- `PC-F2-15` 当工具成功验证只看能否执行时，正负过程奖励都可能诱导退化：惩罚失败 → 调用率为 0；正确且成功工具 bonus → verifier hack（litscan:70458 negative_results §4）。
- `PC-F2-18` 当用过程奖励优化工具时，先声明 GT 可用的信息、动作 token 与观察 token 的路由，并核对两层价值目标与正则的符号（litscan:56625 lesson）。
- `PC-F3-02` 当效率奖励把策略推向单一行为时，几十步内就会塌缩（litscan:76860 §4.5：50 步内 always help），应在训练早期每步记录动作频率，而不是只看最终 checkpoint。
- `PC-F3-02` 当使用 GRPO 时，统计全同奖励组比例（litscan:51030 AppC.3 无 SSR 时达 90%），这部分组不提供任何梯度。
- `PC-F3-04` 当效率奖励只在"组内存在无工具正确样本"时生效时，先确认 warm-start 后每组的无工具样本数，否则 strict 奖励不触发（litscan:76860 FAIL 字段）。
- `PC-F3-06` 当 reward 使用"动作后的错误区"时，注意与"动作前"的区别（litscan:62697 PIT：正文 click reward 在执行后算 FP/FN，可能与修正冲突）。
- `PC-F3-07` 当 validator 用 GT 框与检测区域时，把修正集记为训练暴露集，不称独立验证（litscan:75661 LESSON）。
- `PC-F3-09` 当多轮奖励存在"先错再改"激励时，核清未来奖励是否回传前轮；写成 sum 不代表实现了跨轮 reward-to-go（2409.12917 PIT）。
- `PC-F3-13` 当组条件奖励依赖"组内有某类样本"时，先统计每步满足条件的组比例；比例接近 0 时奖励改动等于没做（litscan:76860 FAIL）。
- `PC-F3-15` 当成功工具定义不清时，条件奖金仍可奖励冗余（litscan:63893 LESSON）。
- `PC-F4-01` 只奖召回时**：策略会枚举框到不作答。应同时加 precision 项，并监控空答率（litscan:72866 Table8）。
- `PC-F4-01` 框按低分辨率宽高给出、裁图却取原图时，要保持比例对应（litscan:63255 Eq10）。
- `PC-F4-02` 若必须给工具分**：要求工具先于终答（2512.08511 Sec.5.3）。同时算一遍合法直答与合法调用的奖励差，确认结构上不偏向调用（2512.08511 Eq.3 代入）。
- `PC-F4-04` 用判官奖励工具时**：同时记录当前策略读入证据后的答案变化，并明确空工具分支、分量取值范围和梯度路由（litscan:63126 lesson）。
- `PC-F4-05` 以证据路径做监督时**：先写清 pending、重复、失败重试的记账规则；保留终答奖；把参考路径和判官与策略隔离（2609.03493 lesson）。
- `PC-F4-05` 感知分平均多个二值 probe 后是多值奖励**：端点过滤识别不了中间值的常数组（litscan:65189 pitfalls）。
- `PC-F4-07` 用隐式奖励自筛时**：打分用的 reference 与 DPO 用的 reference 要分别存版本，并审计 SFT 回填比例（litscan:79304 lesson）。
- `PC-F4-08` 反事实 bonus 能改善答案时**：要分别审计三件事：奖励的输入、实际被更新的 token、采样分布。否则无法推断裁图动作的信用（litscan:76688 lesson）。
- `PC-F4-09` 奖励依赖裁图后的分辨率时**：原图特征遮罩不等价于真实裁图。应保留 crop 重编码，并单独核算开销（litscan:77968 lesson / App B.4）。
- `PC-F4-12` 组样本筛选**：训练时剔除了过易和过难的样本，阈值未知，因此不能把收益全部归给奖励（litscan:78316 pitfalls）。
- `PC-F4-14` 当过程奖励只核对文本一致性时**：要用独立的几何或像素证据来评估，不能把复述当作 grounding（litscan:70540 lesson）。
- `PC-F4-19` teacher-forced 的金答案只能放在独立的 reward pass 中，不能注入真实的后续状态（2605.16416 App.E pitfalls）。
- `PC-F5-12` 当外部视觉 judge 读图失败会降级为纯文本时，必须记录 fallback 频率，频率上升即停（2609.37190 pitfalls，F4 digest）。
- `PC-F5-14` 当给外部 judge 更长的轨迹上下文时，与人评的一致性可能下降（2410.14803 §6.3）。
- `F5-lessons` 当显式加 format 奖励时，它会挤占准确率信号并轻微有害，应当默认置 0、只用正确性。（2607.14547 AppC p.13）
- `F5-lessons` 当用外部 LLM judge 评轨迹时，给它更长的上下文反而可能降低与人评一致性，应当在固定上下文长度下审计 judge。（2410.14803 §6.3）
- `F5-lessons` 当外部视觉 judge 读图失败会降级为纯文本时，必须记录 fallback 频率，频率上升即停训。（2609.37190 AppB.2，F4 digest）
- `F5-lessons` 当用 chosen 回答当正确、用自动一致性过滤构造 judge 训练数据时，它不等于逐条人工核验，应当在审计中单独标出。（litscan:77236 §3.3/A）
